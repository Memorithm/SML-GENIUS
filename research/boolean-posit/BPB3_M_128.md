# BPB3-M/v0 — reversible 128-coefficient BPB3-K microblock

**Research-only prototype.** BPB3-M means a proposed **microblock**
layout, not a replacement for BPB-3/v0 or BPB3-K, and not a new
quantization algorithm.

## Exact wire contract

One BPB3-M/v0 microblock contains **128 coefficients / 56 bytes**:

| Field | Bytes | Meaning |
| --- | ---: | --- |
| Two 64-coefficient groups, three little-endian u64 planes each | 48 | BPB3-K's negative, bit0, bit1 planes verbatim |
| Eight signed 6-bit subgroup scales, LSB-first densely packed | 6 | Original ggml Q3_K scale codes (0..63 means scale -32..31), groups of 16 |
| Shared global FP16 scale, little-endian | 2 | Unchanged ggml Q3_K FP16 bits |

Total: 56 bytes / 128 = **3.5 bits per coefficient**.

The underlying signed integer coefficient remains **[-4,+3]**, encoded
identically to BPB3-K. Two 128-weight microblocks are generated from one
BPB3-K superblock (110 bytes / 256) using **112 bytes**, because the
2-byte global FP16 scale is duplicated. At equal 256-coefficient scope:
+2 bytes, i.e. **+1.81818% total storage**. Compare also against
BPB-3/v0's *distinct* 26 bytes / 64 (3.25 b/w). Do not conflate formats.

The six local scale bytes are a *new canonical packing*, not an original
GGUF 128-coefficient Q3_K block. Original Q3_K is specified at 256
coefficients. The microblock is not claimed to be directly readable by
llama.cpp or GGUF loaders without an adapter.

## Backward-compatible transcode

1. Convert the original 110-byte Q3_K superblock to BPB3-K, preserving
   every coefficient, sixteen 6-bit scales and the original global FP16.
2. Split BPB3-K's 96-byte bitplanes into two 48-byte 128-value halves.
3. Each half holds its original eight six-bit scale values packed into
   six bytes and duplicates the global two-byte FP16 scale.
4. A join function requires exactly **the same raw FP16 bits** in both
   microblocks. It restores the **exact 110 original BPB3-K bytes**.
   Different global scales are rejected because they would imply a
   different quantization contract.

This splitting is **lossless relative to BPB3-K and therefore Q3_K's
quantized reconstruction**. It does **not** improve Q3_K's approximation
to the original unquantized model weights.

The direct kernel consumes only the 56-byte BPB3-M block and two u64
bipolar input masks (16 bytes); there is no 128-value FP32 staging tensor
and no allocation. It returns an exact integer-weighted sum and the
unchanged global FP16 bits. Floating-point reduction ordering is not
defined. Non-finite metadata is not used as evidence of usable inference.

## Trade-offs and hypotheses

- **Possible benefit:** processing one 128-coefficient half can read
  56 contiguous logical weight bytes. A carefully written BPB3-K kernel
  could **also** selectively read one 48-byte half of the bitplanes plus
  the 14-byte original shared metadata (**62 logical bytes**), rather than
  all 110 bytes. Thus the fair selective-access control is **56 vs 62
  logical bytes**, not 56 vs 110; neither determines cache-line or DRAM
  traffic. This only matters for a real partial-use workload. For a full
  256-coefficient dot, two microblocks use *more* total bytes and may
  incur more address/branch overhead.
- **Potential cost:** duplicated FP16 (+1.818%), different scale unpacking,
  independent indexing and cache line crossings. A 56-byte block is
  **not** guaranteed to occupy exactly one physical 64-byte cache line;
  an aligned or padded 64-byte resident layout would be 4.0 b/w.
  Physical bytes fetched, register usage, NUMA locality and actual
  allocator layout all require measurement.
- **Not established:** any speedup, cache saving, lower energy, accuracy
  improvement, real-model benefit, SIMD advantage or GPU advantage.

## Qualification gates

The standalone Rust tests should establish:
- exact join(split(BPB3-K)) bytes for heterogeneous bitplanes and
  unusual FP16 metadata (including NaN/Infinity *bits*);
- bitwise numerical reconstruction against the original Q3_K decoder
  for finite scales;
- exact integer equality: dot(M-left) + dot(M-right) = dot(K-full)
  on matched bipolar input masks;
- signed [-4,+3] extrema, wrong lengths and mismatched FP16 metadata.

Physical performance must compare BPB-3/v0, BPB3-K (256), paired
BPB3-M (2×128), original Q3_K, and an **optimized** Q3_K CPU
implementation at identical numerical weights and full workload.
Add a *separate* partial-use case if claiming selective 128-weight
access benefit. Time conversion separately, measure memory activity
and physical DRAM reads; do not substitute serialized bytes for CAS
read counts. Run on self-hosted hosts only with admission through
Memorithm/RemoteOps, without interrupting active jobs.
