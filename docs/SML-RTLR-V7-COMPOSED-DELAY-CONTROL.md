# RTLR-V7 — composed, noisy and context-switched delays against a calibrated Boolean control

Status: exploratory CPU measurement (x86_64 Linux, Rust 1.89, release), run
after the protocol below was written but **not preregistered in a separate
commit**. Synthetic ANF features; not a trained SML25B/physical MOR model; no
language-model, speed or memory claim.

## Question

RTLR-V6 showed that the cost gate refuses recurrence when a simple Boolean
ring is already optimal. That tested the switch, not whether recurrence ever
pays. Here the Boolean control is made **equally informed and calibrated**
(`CalibratedDelayReadout`: Dirichlet-smoothed counts of the target over the
joint address of the delays that define the label, fitted on TRAIN and frozen
before DEV) and the tasks are made harder in the three ways the V6 report
listed: several delays composed, label noise, and a context that selects the
delay.

## Protocol

- Bench: `sml-rtlr-v7-composed-bench TASK SEED UNIQUE_DIR`; one tab-separated
  `RTLR_V7_COMPOSED_V1` line per trial.
- Features: parity of `source[i-lag-1] & source[i-lag]` on uniform random
  bytes (the V3–V6 ANF delay feature). Label noise flips the label when an
  independent uniform byte is below 26 (10.16 %), so the irreducible loss of
  a noisy task is H(26/256) = 0.4733 bit/position.
- Tasks: 0 `Noisy` = f(64) ⊕ noise; 1 `Xor2` = f(16) ⊕ f(300), noiseless;
  2 `Xor2Noisy` = f(16) ⊕ f(300) ⊕ noise; 3 `Context` = (f(1) ? f(16) : f(300))
  ⊕ noise.
- Data: 3 TRAIN documents × 65 536 positions (fit), one disjoint DEV document
  of 65 536 positions (different generator seed), 1 024-byte causal halo.
- Arms scored on the same DEV positions:
  - `joint`: calibrated readout over **all** declared delays of the task;
  - `first_lag`: calibrated readout over the first declared delay only;
  - `prior`: TRAIN base rate only;
  - `V3`: recurrent `RtlrElastic::new_v3` trained online on the fit documents;
  - `V4`: `RtlrBooleanHybrid` with the preset delays [1, 16, 128, 1023].
- Seeds 11/23/37 initialise the recurrent models only.

## What this does and does not show

- The equally informed calibrated control reaches the entropy floor on every
  task, including composition and context switching. On these tasks there is
  **no residual for recurrence to explain**: it cannot win.
- The recurrent arms are at the level of a coin (1.002–1.005 bit, slightly
  worse than the base-rate prior). They did not learn any of the delays in
  three documents of online training. This agrees with RTLR-V5, where V3 alone
  also failed lag 64 and 1 023. V4 fails the XOR and context tasks for a
  structural reason: it mixes single-delay experts, which cannot express a
  parity of two delays.
- The single-lag control (`first_lag`) fails exactly where composition is
  needed (tasks 1–3), so the joint address is what the control needed, not a
  larger model.
- **Limitation 1:** the controls are given the delays that define the label.
  The TRAIN lag miner (RTLR-V5, fixed in #622) tests single-lag marginal
  dependence, and an XOR of two independent delays has zero marginal
  dependence on each, so it cannot discover tasks 1–3. This study bounds what
  an informed control achieves; it is not a discovery result.
- **Limitation 2:** the seeds change only the recurrent models' initial
  weights; data seeds are fixed, so the three rows per task are not
  independent samples.
- **Limitation 3:** the tasks are generated by the same feature family the
  Boolean control reads. They test whether recurrence adds information beyond
  that family, not natural-language behaviour.

## Consequence for the next step

A recurrence advantage can only be claimed on a task whose label depends on
information that is **not** a function of a bounded set of delayed Boolean
features (for example a latent state accumulated over a window longer than the
ring, or a counter), and only against this calibrated control. Candidate next
tasks: running parity over an unbounded window, and a delay that is itself
encoded in earlier bytes.
