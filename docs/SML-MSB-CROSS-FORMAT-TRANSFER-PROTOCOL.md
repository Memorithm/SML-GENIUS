# MSB-first byte factorization — preregistered source-format transfer probe (2026-10-19)

## Fixed protocol before measuring

Previous PR #624/#626 reported exploratory MSB gains on project Markdown DEV files. This standalone Rust benchmark asks whether the gain transfers to *disjoint Rust source files*, survives a real four-bit deployment export, and whether it generalizes poorly to IID uniform octets. This is **not** independent external-author evaluation, language model training, or a 50M/25B run.

Models: IndependentBits historical factorization versus MsbTree (8 conditioned decisions, binary prefix tree). Both have fresh independent disk f32 masters of 128 pages × 1024 slots = 131072 physical learnable parameters, learning rate 0.3, up to 128 cached pages. Each sees identical TRAIN input order for two epochs, with the three distinct TRAIN document rotations 0/1/2 mapped explicitly to seeds 11/23/37. (A preliminary probe incorrectly used seed % 3, causing seeds 11 and 23 to share the same rotation; its native evidence remains archived separately as exploratory and is superseded by the exact revised SHA.) **Same physical parameter count does not imply same effective function-class capacity** (8 vs 255 output heads). Seeds reorder data only; not independently generated corpora or random weight initializations.

TRAIN: first 16384 bytes or complete file if shorter from README.md, BOOTSTRAP.md, docs/SML-0-SPEC.md, independently with 2-byte context reset at file boundaries. DEV: first 16384 bytes from crates/sml-core/src/byte_factorization.rs, crates/sml-core/src/rtlr_cost_gate.rs, crates/sml-core/src/anf_delay_line.rs, plus 16384 deterministic IID bytes generated by SplitMix64 with fixed seed 0x871e17ca456f1042. No DEV data is provided during weight fitting or used to select hyperparameters; all TRAIN/DEV byte streams are SHA256 fingerprinted, and SHA collisions abort.

For each arm: fit, checkpoint, reopen F32 to check persisted factorization, export genuine Q4 nibble weights, score both F32 and Q4 DEV loss in bits/byte on identical position counts, report actual touched distinct parameters, exact master/Q4 physical bytes, TRAIN and DEV CPU speed. Results may be negative; do not force MSB improvement. Each native host emits 3 seeds × 2 arms × 4 DEV panels = **24 strict MSB_TRANSFER_V1 rows**, 15 tab-separated fields: schema, seed, panel, mode, TRAIN target bytes, TRAIN document count, unique touched parameters, physical capacity, f32 master bytes, Q4 export bytes, DEV SHA256, F32 DEV bits/byte, Q4 DEV bits/byte, TRAIN million target bytes/sec, F32 DEV million target bytes/sec. All document labels are naturally causal next bytes.

Safety: source-code-only DEV is a different genre but still from *this repo*, not independent external corpus. In particular the old inspected project Markdown DEV cannot be reused to claim fresh generalization. The IID negative control may show MSB worse than independent, which must be reported. Never claim this validates 25B or GPU performance. The tested sparse atlas is fixed hashed routing, not a fully learned MOR/ANF architecture; 131072 physical parameters are capacity, not all necessarily updated.
