# SML-50M S3a: preregister multi-Parquet unique-source eligibility audit

Date: 2026-10-21. Protocol frozen BEFORE implementing audit. Owner: SML-GENIUS; RemoteOps hosts tooling but never promotes the model. Research-only. Existing S1b/S2a model and untouched DEV remain independent and unchanged.

## Objective
Run a **read-only candidate audit**, NOT model fitting, for nine additional PleIAs/common_corpus Hugging Face shards `common_corpus_1/subset_100_2.parquet` through `subset_100_10.parquet`, immutable HF revision `307910e4c5d040d6f318e6edf2a2b97849155771` with per-shard SHA256 pin from existing RemoteOps `.github/workflows/sml-hf-common-corpus-500mib.yml`. The original `subset_100_1.parquet` is the baseline and MUST NOT be recounted as new.

A physically measured 81,314,949 unique-byte S1b TRAIN corpus reached 10,445,060 distinct learned slots in 50,000,896 addressable. The successful S2a eight further epochs over that exact text added 650,519,592 bytes of **replayed exposure** and 88,463,035,456 parameter updates, zero *additional* touched slots, F32 DEV BPC 3.868702618→3.865978150, Q4 DEV BPC 4.028135208→4.007063135. Hence genuine new, independent text takes precedence over more epochs.

## Scope and admission
- Only **exact-label CC0 and CC-BY-3.0/4.0** candidates, with original immutable source/revision, nonempty identifiers, creator AND title, and plain UTF-8 documents of 128..2,097,152 bytes. Keep source license string and attribution; CC-BY requires downstream attribution. Metadata descriptions are not independent legal certification. Explicitly exclude `PD_CLAIM`, CC-BY-NC, CC-BY-SA, unknown, ambiguous or blank licenses and identifiers.
- SHA256 dedup by document across every new shard and **entire S1b original source** (not just trained bytes). For this first strict audit, exclude any creator whose normalized name appeared in the 28,294-record S1b original provenance (including TRAIN and DEV). That conservative group exclusion avoids certain cross-split leakage but is NOT a guarantee against anonymous aliases, derivative text, near duplicates or work-family overlap. Publication/training admission requires separate near-duplicate screening and independent legal/attribution review.
- Do NOT write decoded source text or author identifiers into GitHub public Actions logs or artifacts. Restrict offline Rust audit output to aggregate eligibility statistics (counts, bytes, rejection reasons, unique hashes in host-local restricted receipt) and exact source/probe commit SHAs. Never open 2024 TEST or SEC G0.
- Limit scanner to bounded per-document memory and one Parquet shard at a time on Dell, with immutable per-shard SHA verified prior to use; no network calls from scanner. Existing REST GitHub state is orchestration evidence, not attestation of physical host identity.
- Initial discovery target: 512 MiB **additional** distinct eligible UTF-8 candidates plus at least 32 MiB independent DEV potential, **not** merely downloads or 512 MiB repeatedly exposed. The final 512-MiB TRAIN and author-disjoint DEV assignment must be preregistered only once available document metadata is measured; the audit itself must not train or use DEV loss.
- Fail closed if downloads differ in SHA, sample groups overlap baseline, source is malformed, disk/memory budget insufficient, or minimum is absent. Report true shortfall and propose another shard/legally qualified source; do not silently change license classes or source gate.
- The audit is **S3a CANDIDATE_ONLY**. S3b must add provenance-preserving bounded per-document materialization, independent near-duplicate and author-group validation, and a legally signed-off manifest BEFORE training 50M. Compare later S3 DEV/test to a matched ngram4 baseline on identical untouched data. Do not claim 25B or generally superior training speed.
