# Four-domain cumulative supervisor bootstrap

The opt-in bounded simulation accepts r1_train=FILE and r1_sha=HEX only
with the existing bilingual configuration. Corpus bytes are read once,
bounded and SHA-256 verified. The job identity binds that digest; the
native R1 oracle separately verifies every TRAIN label. The first cycle
consolidates two L1 banks, one R1 bank (nine closed expressions) and fresh
mathematical functions through the same engine and atomic store transaction.
Every later cycle directly compiles and examines the retained R1 bank,
without teacher inference or relearning. L1 and R1 are counted as prior
competence re-examinations, not new acquisitions. This qualification uses
oracle-generated TRAIN labels, not live Inkling inference.

The CI checks actual daemon restarts, immutable prior manifest records,
eight new mathematical entries, three prior banks and 11 total records.
It requires 589824 compiled and 589824 restored R1 predictions on the
second cycle. Existing math-only and bilingual modes retain their identity
and accounting. This does not claim general Rust ability, novel language
learning or production deployment. R2/R3 remain separate.
